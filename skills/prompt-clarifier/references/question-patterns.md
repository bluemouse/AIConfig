# Question Patterns

Ask only questions whose answers can change the work. The dimensions to probe when
unresolved: outcome and intent (what should be true when finished; which decision the
output supports), deliverable form, scope (in/out, what must remain unchanged),
operational definitions (an example and a non-example; a measurable threshold for
subjective terms like "fast" or "secure"), authoritative inputs when sources disagree,
constraints and their priority order, acceptance criteria, environment, and
authority/reversibility limits (may I modify files directly, publish, delete, spend).

## Conflict resolution

Use this structure when requirements or sources contradict:

```text
I found a conflict:
- Requirement A: <requirement and consequence>
- Requirement B: <requirement and consequence>

Which should take priority?
  a) A
  b) B
  c) Use this alternative: <feasible compromise>
```

## Adaptive follow-up

Ask a follow-up only when the previous answer creates a necessary branch. Do not ask
both branches in advance.
