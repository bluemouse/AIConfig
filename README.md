# AI Configuration for Cursor, GitHub Copilot, and Claude Code

This repository provides a **portable, single-root layout** for AI-assisted development across Cursor, GitHub Copilot, and Claude Code.

### Bootstrap skills and installed skills

| Term | Location | Role |
| --- | --- | --- |
| **Bootstrap skill** | `skills/<name>/` | Authoritative source. Edit `SKILL.md`, references, and scripts here. |
| **Installed skill** | `.agents/skills/<name>/` | Verbatim copy of the bootstrap package, generated and untracked — every tool reads this copy. |
| **Claude Code bridge** | `.claude/skills` | Symlink to `../.agents/skills`, auto-created on install so Claude Code discovers the skills. |

Install a bootstrap skill with `install_portable_skill.py` to copy it to `.agents/skills/`. Re-run after edits to `skills/<name>/`.

### Bootstrap agents and installed agents

| Term | Location | Role |
| --- | --- | --- |
| **Bootstrap agent** | `agents/<name>/` | Authoritative source. Edit `AGENT.md` here. |
| **Installed agents** | `.claude/agents/<name>.md`, `.github/agents/<name>.agent.md` | Two real copies: the Claude/Cursor file (verbatim from AGENT.md) and the Copilot transform. |

Install a bootstrap agent with `install_portable_agent.py`. Re-run after edits to `agents/<name>/`.

### Bootstrap commands and command-skills

| Term | Location | Role |
| --- | --- | --- |
| **Bootstrap command** | `commands/<name>/` | Authoritative source. Edit `COMMAND.md` here. |
| **Command-skill** | `.agents/skills/cmd-<name>/SKILL.md` | Single install output with `disable-model-invocation: true` — every tool exposes it as `/<name>`, and the model never self-invokes it. The install dir carries the `cmd-` prefix; the slash name does not. |

Install a bootstrap command with `install_portable_command.py`. Re-run after edits to `commands/<name>/`. Invoke as `/command-name` in each IDE.

## Install a bootstrap skill

Use this workflow when a complete bootstrap skill already lives under `skills/<name>/`.

### 1. Author the bootstrap skill

Create or edit the bootstrap skill at `skills/<name>/`:

```
skills/<name>/
├── SKILL.md              # Tool-neutral skill (frontmatter: name, description)
├── references/           # Optional: docs loaded on demand
├── scripts/              # Optional: executable helpers
└── assets/               # Optional: templates, binaries, etc.
```

**Shared `SKILL.md` rules:**

- Keep the body **tool-neutral** — tool-specific mechanics belong in a `## Tool notes` section of the body (H2 with `### Claude Code` / `### Cursor` / `### GitHub Copilot` H3 subsections as needed), not in separate per-tool files
- Resolve `<SKILL_ROOT>` as the directory containing the skill's `SKILL.md`
- Put bundled resources only under `references/`, `scripts/`, or `assets/`
- Cross-link sibling skills with relative paths (e.g. `../cpp-coding/SKILL.md`) — these resolve after install under `.agents/skills/`
- The skill directory must be a direct child of a skills root (e.g. `skills/<name>/` or `.agents/skills/<name>/`); category subfolders (`skills/<category>/<name>/`) are rejected by the validator

### 2. Install (single-root copy)

From the repository root (requires `skill-creator` scripts):

```bash
python skills/skill-creator/scripts/install_portable_skill.py \
  --root . \
  --name <skill-name> \
  --source skills/<skill-name> \
  --overwrite
```

The script:

1. Copies the bootstrap skill to `.agents/skills/<skill-name>/`
2. Ensures the Claude Code bridge symlink `.claude/skills -> ../.agents/skills` exists (refuses when a real directory occupies the path — purge the legacy install first)
3. Validates the installed skill with `quick_validate.py`

Install multiple related skills in any order when they cross-reference each other — e.g. the C++ cluster (`cpp-coding`, `cpp-memory-guide`), the Kotlin/Gradle cluster (`kotlin-coding`, `gradle-dev`, `gradle-android-dev`), or the GPU stack (`gpu-rendering-guide`, `vulkan-dev`, `slang-dev`, `shader-guide`, `glsl-coding`, `usd-hydra2-dev`) link via `../<sibling>/SKILL.md`.

### 3. Validate (optional manual check)

```bash
python skills/skill-creator/scripts/quick_validate.py .agents/skills/<skill-name>
```

### 4. Reload

Only Claude Code needs a reload (restart or reload the session): Cursor
and VS Code (Copilot) discover `.agents/` and `.github/agents/` natively
on their next session.

### 5. Re-install after edits

Edit the bootstrap skill under `skills/<name>/`, then re-run the install command. The bootstrap skill remains the source of truth; `.agents/skills/` is the generated output.

**Example — install the C++ cluster:**

```bash
for skill in cmake-dev cpp-coding cpp-memory-guide; do
  python skills/skill-creator/scripts/install_portable_skill.py \
    --root . --name "$skill" --source "skills/$skill" --overwrite
done
```

**Example — install the GPU rendering stack:**

```bash
for skill in gpu-rendering-guide vulkan-dev slang-dev shader-guide glsl-coding; do
  python skills/skill-creator/scripts/install_portable_skill.py \
    --root . --name "$skill" --source "skills/$skill" --overwrite
done
```

**Example — install the Kotlin/Gradle cluster:**

```bash
for skill in kotlin-coding gradle-dev gradle-android-dev; do
  python skills/skill-creator/scripts/install_portable_skill.py \
    --root . --name "$skill" --source "skills/$skill" --overwrite
done
```

**Example — install the painting-engine skills:**

```bash
for skill in mypaint-engine-dev krita-engine-dev; do
  python skills/skill-creator/scripts/install_portable_skill.py \
    --root . --name "$skill" --source "skills/$skill" --overwrite
```

## Create a new portable skill (from scratch)

Use the installed **skill-creator** skill (or read `skills/skill-creator/SKILL.md`) when starting with an empty scaffold:

```bash
python skills/skill-creator/scripts/create_skill.py --root . --name my-skill
```

This creates:

- `.agents/skills/my-skill/` — the installed skill with placeholder resources

Validate before and after editing:

```bash
python skills/skill-creator/scripts/quick_validate.py .agents/skills/my-skill
```

For a standalone skill in one location (personal install or single-tool copy):

```bash
python skills/skill-creator/scripts/init_skill.py my-skill --path ~/.cursor/skills
```

The path must be a skills root (a directory named `skills`) with the skill created directly inside it — category subfolders (`skills/<category>/<name>/`) are rejected by `quick_validate.py`'s flat-root check (and by `install_portable_skill.py`'s source check), not by `init_skill` itself.

See `skills/skill-creator/references/portable-skill-layout.md` for path conventions and the `## Tool notes` format.

## Create a new portable agent

Use the installed **agent-creator** skill (or read `skills/agent-creator/SKILL.md`). Draft tool-neutral instructions, then scaffold:

```bash
python skills/agent-creator/scripts/create_agent.py \
  --root . \
  --name my-agent \
  --description "What the agent does and when to use it." \
  --instructions-file /path/to/instructions-body.md \
  --overwrite
```

This creates:

- `.claude/agents/my-agent.md` — Claude Code agent (verbatim; Cursor compat-reads it)
- `.github/agents/my-agent.agent.md` — GitHub Copilot agent

Validate immediately:

```bash
python skills/agent-creator/scripts/quick_validate.py --root . --name my-agent
```

See `skills/agent-creator/references/portable-agent-layout.md` for path conventions.

## Standard install paths

When adding assets to this repo or another project, use these locations:

### Single root (all tools)

- `.agents/skills/<skill-name>/` — installed skill (the one real copy); command-skills install at `.agents/skills/cmd-<name>/` (invoked as `/<name>`)
- `.agents/skills/guidelines-<name>/` — guideline skill packages installed into target projects

### Cursor

Cursor reads `.agents/skills/` directly; reload Cursor after adding or changing skills, rules, or commands.

### Claude Code

- `.claude/skills` — bridge symlink to `../.agents/skills` (auto-created on install)
- `.claude/agents/` — custom agent definitions (one dual-target copy)

Restart or reload Claude Code after adding or changing skills, commands, or agents.

### VS Code + GitHub Copilot

- `.github/agents/` — custom agents (`*.agent.md`)
- `.github/instructions/` — scoped instructions (`*.instructions.md`, `applyTo` globs)

Copilot reads `.agents/skills/` directly; reload VS Code after changes so Copilot picks up new files.

## Distribute to another project

Use **`tools/installer.py`** to copy the **portable layout** from this checkout into another project root. This copies this checkout's generated `.agents/skills/<name>/` trees (skills and command-skills; regenerate them with the install scripts on a fresh clone) and the dual-target agent files (`.claude/agents/<name>.md` + `.github/agents/<name>.agent.md`) to the target project root, creating the `.claude/skills` bridge symlink there. It also installs behavioral guidelines from `guidelines/` as skill packages at `.agents/skills/guidelines-<name>/SKILL.md` when explicitly selected (the installer injects `name: guidelines-<name>` frontmatter at install time), so guidelines load through ordinary skill discovery in the target — no AGENTS.md citation needed. Selected members are expanded with their transitive skill dependencies from [tools/dependencies.json](tools/dependencies.json) at install time (see [tools/bundles.md](tools/bundles.md) § Dependency map): selecting a command or agent whose criteria skills are missing pulls them in automatically; uninstall selections are never expanded. It does **not** install bootstrap sources from `skills/<name>/`, `agents/<name>/`, or `commands/<name>/` — run the matching `install_portable_*` script here first, then distribute.

**CLI** (from this repository root):

```bash
# Install all discovered skills, agents, and commands
python tools/installer.py /path/to/other-project

# Install selected skills, agents, or commands
python tools/installer.py /path/to/other-project --skills cpp-coding vulkan-dev
python tools/installer.py /path/to/other-project --agents my-agent
python tools/installer.py /path/to/other-project --commands commit

# Install workflow bundles (see tools/bundles.md and tools/bundles.json)
python tools/installer.py /path/to/other-project --bundles core-dev-workflow
python tools/installer.py /path/to/other-project --bundles extended-dev-workflow --override

# Preview an install without writing anything (the target must already exist)
python tools/installer.py /path/to/other-project --bundles core-dev-workflow --dry-run

# Install the dev-workflow harness (11 skills, 5 commands; validation scripts
# ship inside the dev-workflow-orchestrator skill package)
python tools/installer.py /path/to/other-project --dev-workflow
python tools/installer.py /path/to/other-project --bundles dev-workflow-harness

# Install behavioral guidelines (explicit-only; installs as .agents/skills/guidelines-<name>/)
python tools/installer.py /path/to/other-project --guidelines coding-behavior

# Remove legacy-layout leftovers from an older install of this repo's tooling
# (.ai/, .cursor/{skills,commands,agents}/, .github/prompts/, .github/skills/,
# .claude/commands/, .agents/guidelines/, and .claude/skills/ when it is a real directory)
python tools/installer.py /path/to/other-project --purge-legacy

# Replace existing installs in the target
python tools/installer.py /path/to/other-project --skills cpp-coding --override

# Remove from the target
python tools/installer.py /path/to/other-project --skills cpp-coding --uninstall
python tools/installer.py /path/to/other-project --agents my-agent --uninstall
python tools/installer.py /path/to/other-project --commands commit --uninstall
python tools/installer.py /path/to/other-project --guidelines coding-behavior --uninstall
```

| Flag | Behavior |
| --- | --- |
| `TARGET` | Destination project root (required in CLI mode) |
| `--bundles ID ...` | Bundle ids from [tools/bundles.json](tools/bundles.json) or `target-bundle`; a bundle may include skills, agents, and commands (see [tools/bundles.md](tools/bundles.md)) |
| `--skills NAME ...` | Skill slugs to install or uninstall (default: all discovered unless `--bundles` is set); at install time the selection is expanded with the slugs' transitive skill dependencies (see [tools/bundles.md](tools/bundles.md) § Dependency map) |
| `--agents NAME ...` | Agent slugs to install or uninstall (default: all discovered); install selections auto-select each agent's criteria skills (see [tools/bundles.md](tools/bundles.md) § Dependency map) |
| `--commands NAME ...` | Command slugs to install or uninstall (default: all discovered); commands install as command-skills under `.agents/skills/cmd-<name>/` with `disable-model-invocation: true`; install selections auto-select each command's engine skills (see [tools/bundles.md](tools/bundles.md) § Dependency map) |
| `--guidelines NAME ...` | Behavioral guideline names (under `guidelines/`) to install or uninstall. Explicit-only — never part of the default install or bundles. Installed as the skill package `.agents/skills/guidelines-<name>/` in the target (loads via skill discovery) |
| `--dev-workflow` | Alias for `--bundles dev-workflow-harness`: installs/uninstalls the complete dev-workflow harness (orchestrator, phase skills, and commands — validation scripts ship inside the orchestrator skill; see [tools/bundles.md](tools/bundles.md) for full membership) as a unit |
| `--purge-legacy` | Remove the target's pre-single-root install leftovers (`.ai/`, `.cursor/skills|commands|agents/`, `.github/prompts/`, `.github/skills/`, `.claude/commands/`, `.agents/guidelines/`, `.agents/tools/`, and `.claude/skills/` only when it is a real directory — the bridge symlink is left alone). Composes with the kind selectors or runs standalone |
| `--override` | Replace existing paths in the target; without it, skip and report |
| `--dry-run` | Preview the install/uninstall/purge without writing anything to the target (including the `.claude/skills` bridge symlink); the target must already exist |
| `--uninstall` | Remove the selected skills, agents, commands, and guidelines from the target project (a missing target errors with exit 2 rather than reporting an empty success, so teardown scripts fail loudly) |
| *(no arguments)* | Open a tkinter GUI with skill/agent/command checkboxes and a **Bundles** panel for workflow batch selection |

Without `--override`, existing paths in the target are skipped. `--dry-run` previews the selected install, uninstall, or purge without writing anything to the target — the target must already exist, and the output is prefixed with `Dry run — no changes were made:`. The script refuses to install skills, agents, or commands into this AIConfig repo itself (use `install_portable_*` for those); `--guidelines` may target `.` to regenerate local untracked copies. Reload Claude Code in the target project after install (Cursor and VS Code rediscover natively). Bundle definitions live in [tools/bundles.md](tools/bundles.md) (human-readable) and [tools/bundles.json](tools/bundles.json) (machine-readable).

**GUI:**

```bash
python tools/installer.py
```

- Checkboxes start **unchecked**
- **Bundles** panel: batch toggles plus Select all/none; **Target bundle** appears after a valid target project path is set and selects skills, agents, and commands already installed in that project

## Skills

Skills are folders with a `SKILL.md` (YAML frontmatter: `name`, `description`) plus optional bundled resources. The agent discovers skills from frontmatter and loads the body progressively when relevant.

**Portable (recommended):** author a **bootstrap skill** under `skills/<name>/`, install to produce the single real copy in `.agents/skills/<name>/` that all tools read.

**Standalone:** copy the full skill folder into one tool path (e.g. `~/.cursor/skills/<name>/`) without the single-root layout.

**Package an installed skill for distribution:**

```bash
python skills/skill-creator/scripts/package_skill.py .agents/skills/my-skill
```

**Copy installed skills, agents, and commands to another project** (single-root layout; see [Distribute to another project](#distribute-to-another-project)):

```bash
python tools/installer.py /path/to/other-project
```

## Meta-skills: skill-creator and agent-creator

Bootstrap, validate, and install workflows are handled by the **skill-creator** and **agent-creator** installed skills — not separate custom agents.

**Create a skill from templates** (example chat prompt):

```text
Use skill-creator to bootstrap mypaint-engine-dev from a staging draft,
validate the bootstrap under skills/mypaint-engine-dev/, and install with
install_portable_skill.py.
```

**Install or refresh a bootstrap skill manually:**

```bash
python skills/skill-creator/scripts/install_portable_skill.py \
  --root . --name my-skill --source skills/my-skill --overwrite
```

**Batch-install related skills:**

```bash
for skill in gpu-rendering-guide vulkan-dev slang-dev; do
  python skills/skill-creator/scripts/install_portable_skill.py \
    --root . --name "$skill" --source "skills/$skill" --overwrite
done
```

**Create a custom agent** (example chat prompt):

```text
Use agent-creator to bootstrap code-reviewer under agents/code-reviewer/, validate,
and install with install_portable_agent.py.
```

**Direct agent scaffold** (no bootstrap):

```bash
python skills/agent-creator/scripts/create_agent.py \
  --root . --name my-agent --description "…" --instructions-file body.md --overwrite
```

Commit messages: use the installed **commit-message-writer** skill (or ask in chat to draft a Conventional Commit from staged changes).

## Rules (Cursor)

Rules are `.mdc` files in `.cursor/rules/` with frontmatter controlling `globs` and `alwaysApply`. They apply automatically based on scope. Keep rules small and composable.

## Agents

Portable custom agents use a dual-target layout:

- `agents/<name>/` — bootstrap source when present (edit `AGENT.md` here, then install)
- `.claude/agents/<name>.md` — Claude Code copy (verbatim from AGENT.md; Cursor compat-reads it)
- `.github/agents/<name>.agent.md` — GitHub Copilot copy

Use the **agent-creator** skill to scaffold new agents or **install_portable_agent.py** to install bootstrapped agents under `agents/<name>/`. Tool-specific agent mechanics belong in a `## Tool notes` section of the bootstrap `AGENT.md`.

**Bootstrap validate + install:**

```bash
python skills/agent-creator/scripts/quick_validate.py --bootstrap-source agents/<name>

python skills/agent-creator/scripts/install_portable_agent.py \
  --root . --name <name> --source agents/<name> --overwrite
```

Reload Claude Code after install so custom agents are rediscovered (Cursor and VS Code rediscover `.github/agents/` natively).
